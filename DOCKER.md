# Запуск в Docker

Образ содержит консольное приложение и исходную SQLite-базу `tracker.db`.
SQLite-драйвер написан на Go, поэтому приложение собирается с `CGO_ENABLED=0`.
В финальный образ попадают только исполняемый файл и база данных.
Приложение запускается непривилегированным пользователем из `/app`;
этому пользователю доступны запись в базу и создание SQLite journal.

Замените `YOUR_DOCKER_ID` своим логином Docker Hub:

```sh
docker build --tag YOUR_DOCKER_ID/parcel-tracker:v1 .
docker run --name parcel-tracker YOUR_DOCKER_ID/parcel-tracker:v1
docker logs parcel-tracker
docker inspect --format '{{.State.ExitCode}}' parcel-tracker
```

Ожидаются сообщения о регистрации посылок, изменении статуса и вывод списков.
Программа консольная: после выполнения сценария контейнер останавливается
с кодом `0`. Публиковать порты и создавать `compose.yaml` не требуется.

Изменения SQLite сохраняются в слое контейнера до его удаления. Новый контейнер
начинает с исходной базы из образа. Для сохранения данных между контейнерами
можно подключить копию базы через bind mount (не исходный файл репозитория).
